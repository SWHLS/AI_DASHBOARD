교육생 배포자료

클릭보다 오래 남는 것

생성형 AI를 활용한 업무 생산성 향상 · 한국중부발전(주)

교육 중에는 화면 따라가시느라 바쁘실 겁니다. 이 자료는 그때 못 들으신 것과, 회사 돌아가셔서 다시 하실 때 필요한 것만 모았습니다. 클릭 순서는 화면에 있으니 여기엔 안 적었습니다. 대신 왜 그렇게 하는지를 적었습니다. 그건 도구가 바뀌어도 안 변합니다.

오늘 하루를 한 문장으로

계산은 AI가 대신해 주지만, 무엇을 기준으로 삼을지는 여전히 사람이 정합니다. 오늘 실습에서 그 "기준"을 정하는 순간이 몇 번 나옵니다. 그때가 진짜 배우는 지점입니다.

1우리가 만지는 숫자

공공데이터포털에서 받은 그 파일이 무엇인지

회사가 법에 따라 공개해 둔 대기오염물질 배출량 데이터입니다. 한 줄이 호기 하나의 한 달치입니다. 4개년을 합치면 1,488줄인데, 48개월 × 31개 호기라서 그렇습니다.

컬럼뜻
발전기명사업소 (보령·서울·세종·신보령·신서천·인천·제주)
호기명설비 하나 (1호기, GT1, 내연1, 복합2 …)
배출년월월 단위
허용기준이 설비가 넘으면 안 되는 선
평균농도실제로 나온 값
기준과 실측이 짝으로 있습니다

그래서 "몇 ppm 나왔다"가 아니라 "기준의 몇 %를 쓰고 있다"로 말할 수 있습니다. 보고서에서 훨씬 잘 통하는 표현입니다.

호기마다 기준이 다른 이유

실습 중에 기준이 10, 15, 34, 119처럼 제각각인 걸 보시게 됩니다. 연소 방식이 다르고(기력·복합·가스터빈·내연), 설치 시기가 다르고, 입지 지역이 달라서입니다.

그래서 조심할 것

호기끼리 농도 숫자를 그대로 비교하시면 안 됩니다. 자가 다른 저울로 잰 값입니다. 비교하시려면 평균농도 ÷ 허용기준 컬럼을 하나 만드십시오. 그래야 31개 호기가 같은 자 위에 섭니다.

0.0의 정체

SOx·NOx·먼지가 동시에 정확히 0인 달이 있습니다. 측정 오류가 아니라 그 달에 그 호기가 안 돌았다는 뜻입니다.

그런데 엑셀은 이 0을 성실하게 평균에 넣습니다. 정지가 많았던 호기일수록 평균이 낮게 나옵니다. 0은 숫자가 아니라 상태일 때가 있습니다.

이 데이터를 다룰 때 중요한 선

실습 중 "기준을 초과한 호기"가 나옵니다. 그런데 이건 월평균 값입니다. 실제 규제 준수 판정은 굴뚝자동측정기기(TMS)로 잰 훨씬 짧은 시간 단위 값으로 이뤄집니다.

여기서 나온 초과는 위반이 아니라 "들여다볼 이유가 있다"는 신호입니다. 보고서에 쓰실 때 이 구분을 꼭 지켜 주십시오.

2데이터 청소 — 오늘의 핵심

도구가 틀린 답을 내고, 그걸 고치는 장면

2023년 파일에 빈칸(결측)이 42개 있습니다. 이걸 채우는 걸 보간이라고 합니다.

보간은 기술이 아니라 가정입니다

우리 데이터는 달마다 이어지는 시계열입니다. 어느 가정이 더 그럴듯합니까?

실습에서 보시게 될 실패

도구 버튼만 눌러 보간하면 보령 3호기 빈칸에 19가 들어갑니다. 이 호기는 평소 1~2ppm대인데요.

이유는 이렇습니다. 도구가 1,488줄을 전부 한 줄로 세워놓고 평균을 냈습니다. 그 안엔 제주 내연기관 300ppm도 있습니다. 그걸 다 섞은 평균이 석탄 호기 칸에 들어간 겁니다.

기술이 달라진 게 아닙니다. "어디까지가 같은 무리인지"를 사람이 알려준 것뿐입니다. AI가 계산은 잘하지만, 무엇을 기준으로 묶어야 하는지는 그 일을 아는 사람만 압니다. 여러분입니다.

3피벗테이블은 질문 도구입니다

필드를 옮기는 건 화면이 아니라 질문을 바꾸는 일

이 문장 하나만 외우시면 됩니다

[필터] 안에서, [행] 별로, [열]에 따라, [값]은 어떻게 되는가?

합계를 쓰면 안 되는 경우

엑셀 피벗은 숫자를 넣으면 기본이 합계입니다. 그런데 4.26ppm + 3.9ppm = 8.16ppm 이 말이 됩니까?

농도는 애초에 더하면 안 되는 값입니다. 피벗에서 값을 넣은 직후 가장 먼저 하실 일은 값 설정을 평균으로 바꾸는 것입니다.

더해도 되는 값더하면 안 되는 값
발전량(MWh), 배출총량(톤), 건수, 금액 농도(ppm), 비율(%), 효율, 온도

평균이냐 최대냐

같은 데이터인데 최대로 보면 기준 초과가 여러 건 나오고, 평균으로 보면 대부분 기준 아래입니다. 어느 쪽이 맞을까요?

둘 다 맞습니다 — 다른 질문이니까요

최대 = "가장 나빴던 순간에 무슨 일이 있었나" → 안전·환경 관리
평균 = "평소에 어떻게 운영되고 있나" → 설비 성능 평가

보고서 쓰실 때 "평균으로 쓸까 최대로 쓸까" 고민되는 순간이 옵니다. 그때 숫자를 고르는 게 아니라 질문을 고르는 것임을 기억하십시오.

평균만 보고하지 마십시오

어떤 집단을 요약할 때 평균 · 표준편차 · 최대 · 개수 네 개를 세트로 보십시오. 피벗에서 같은 필드를 네 번 끌어다 놓으면 됩니다.

표준편차가 평균에 가까워지면 그 평균은 쓰지 마십시오. 한 덩어리로 볼 수 없는 집단이라는 뜻이고, 더 쪼개야 합니다.

피벗에서 자주 나는 실수

행에 호기명만 넣으면, 발전소가 달라도 이름이 같은 호기가 한 줄로 합쳐집니다. 보령 1호기와 인천 1호기가 섞이는 겁니다.

피벗은 이름이 같으면 묻지 않고 합칩니다. 행에 발전기명을 하나 더 얹으면 해결됩니다. 보고서에 붙이기 전에 "이 행 이름이 진짜 유일한가" 3초만 확인하십시오.

일반 채팅은 배운 지식으로 그럴듯하게 지어낼 수 있습니다. Notebook은 올린 파일에 없으면 없다고 말하고, 답변마다 출처를 붙여 줍니다.

규정집·계약서·기술기준서·회의록처럼 "이 문서 안에서만 답해야 하는" 자료에 쓰십시오. 보고서에 들어갈 문장은 근거를 댈 수 있어야 하니까요.

왜 항상 "HTML과 자바스크립트로만"이라고 쓰나

실습 프롬프트마다 이 문장이 붙습니다. 이유가 넷입니다.

  • 설치가 필요 없습니다 — 브라우저만 있으면 됩니다. 회사 PC에서 중요합니다
  • 파일 하나로 끝납니다 — 메일로 보내면 상대방도 바로 열립니다
  • 그대로 웹에 올라갑니다
  • 데이터가 밖으로 안 나갑니다 — 브라우저 안에서만 처리됩니다

5웹에 올리기 — 왜 필요한가

더블클릭으로는 안 되는 이유

대시보드를 두 번 만드시게 됩니다. 겉은 비슷한데 속이 다릅니다.

① 정적 대시보드② 실시간 대시보드
숫자가파일 안에 박혀 있음구글 시트를 매번 읽어옴
데이터 수정처음부터 다시 만들어야시트만 고치면 끝
더블클릭열립니다 ○안 열립니다 ✕
사내 데이터써도 안전공개됩니다 — 주의
더블클릭으로 안 열리는 이유

파일을 더블클릭하면 주소가 file:///C:/...로 시작합니다. 이건 인터넷 주소가 아닙니다.

브라우저 입장에서 내 컴퓨터 안의 파일은 신원이 확인 안 된 손님입니다. 그런 손님이 바깥 데이터를 가져오겠다고 하면 막습니다. 보안 때문입니다.

웹에 올리면 https://... 주소를 가진 정식 사이트가 됩니다. 신원이 생긴 거죠. 그때부터 통과됩니다. GitHub·Vercel에 가입하는 건 이 대시보드에 주소를 만들어 주려는 것입니다.

구글 시트→ 웹에 게시 (CSV)→ 대시보드가 읽음→ Vercel이 웹에 띄움

GitHub와 Vercel의 역할

  • GitHub = 파일을 보관하는 창고. 그 자체로는 웹사이트가 아닙니다
  • Vercel = 창고를 들여다보고 사이트로 띄워 주는 서비스

파일 이름을 index.html로 바꾸는 이유는, 웹 서버가 주소 뒤에 파일명이 없으면 그 폴더의 index.html을 기본으로 찾기 때문입니다. 전 세계 공통 약속입니다. 전부 소문자여야 합니다.

가장 중요한 주의사항 — 꼭 읽어 주십시오

오늘 쓰는 데이터는 이미 공개된 공공데이터라 웹에 올려도 괜찮습니다.

그런데 회사 돌아가셔서 사내 데이터로 똑같이 하시면 유출입니다.

  • GitHub를 Private으로 해도 Vercel 배포 주소는 공개됩니다
  • 구글 시트를 "웹에 게시"하면 그 순간 공개됩니다 (공유 설정과 다른 기능입니다)

사내 데이터로 만드시려면 ①번 정적 방식을 쓰십시오. HTML 파일 하나 만들어 메일로 돌리면 데이터가 밖으로 안 나갑니다. 아니면 정보보안 부서에 먼저 확인하십시오.

6AI가 만든 것을 믿지 않는 법

이 강의에서 가장 오래 남을 부분

말로 소프트웨어를 만드는 것을 바이브 코딩이라고 합니다. 만들고, 보고, "이건 이렇게 바꿔줘" 하고, 또 보고. 오늘 그걸 하십니다.

실제로 있었던 일 — 이 강의 준비 중에

대시보드를 만들어 배포했더니 화면이 정상으로 떴습니다. 상단에 "동기화 완료"라고까지 나왔습니다. 그런데 숫자가 전부 0.00이었습니다.

원인이 둘이었습니다.

  1. 우리가 실습에서 날짜를 년/월 두 칸으로 쪼갰는데, AI가 만든 코드는 배출년월 한 칸을 찾고 있었습니다. 못 찾으니 1,488줄이 전부 걸러져 0건이 됐습니다
  2. 그런데도 "동기화 완료"라고 표시됐습니다. 파일을 가져오는 데는 성공했으니 코드 입장에선 거짓말이 아니었습니다

게다가 AI가 실패했을 때 대신 보여줄 가짜 데이터를 코드에 넣어뒀습니다. 그래서 로컬에서는 멀쩡히 숫자가 보였고, 배포하고 나서야 문제가 드러났습니다.

여기서 가져가실 두 가지

하나. 전처리에서 내린 결정은 끝까지 따라옵니다. 날짜를 쪼갠 게 마지막 대시보드까지 영향을 줬습니다.

둘. 화면에 숫자가 보인다고 연동된 게 아닙니다. AI는 실패를 성공처럼 보이게 만드는 화면을 자주 만듭니다. 친절한 게 아니라 위험한 겁니다.

검증 습관 세 가지 — 이것만 하셔도 됩니다

  1. 아는 값 하나로 검산하기. 이미 답을 아는 호기 하나를 골라 화면 숫자와 맞춰 보십시오
  2. 이상한 파일 넣어보기. 빈 파일, 한 줄짜리, 한글 깨진 파일
  3. 총계 맞춰보기. 화면에 뜬 건수가 원본 행 수와 같은지
프롬프트에 이 한 줄을 꼭 넣으십시오
실패를 숨기지 못하게 하는 문장데이터를 못 읽거나 결과가 0건이면 "완료"라고 표시하지 말고, 화면에 빨간 배너로 에러 내용과 실제 컬럼 이름을 그대로 보여줘.

이 한 줄이 오늘 겪은 사고를 막습니다.

7복붙용 프롬프트 모음

회사 가셔서 그대로 쓰시면 됩니다

프롬프트를 잘 쓴다는 건

미사여구가 아니라 내가 뭘 원하는지 나부터 정리하는 것입니다. 아래 다섯 칸을 채우십시오. 채우다 막히는 칸이 있다면, 그게 아직 결정 안 한 부분입니다. AI가 못 만드는 게 아니라요.

기본 골격 — 다섯 칸[역할] 너는 ○○를 다루는 △△다. [입력] 어떤 파일·데이터를 받는가. [처리] 무엇을 어떤 순서로 하는가. [출력] 무엇으로 결과를 내놓는가. [제약] 무엇을 쓰고 무엇을 쓰지 말 것인가.
① 결측치 보간첨부한 파일의 결측치를 보간해줘. ○○명, △△명, 날짜컬럼을 고려해서 같은 그룹끼리만 보간할 것. 방법은 앞뒤 값을 이용한 선형 보간. 몇 개를 어떤 기준으로 채웠는지 설명도 같이 알려줘.
② 기초 통계 확인첨부한 파일의 "○○" 컬럼에 대한 기초 통계 분석. 평균, 중앙값, 표준편차, 최소/최대, 사분위수를 표로 정리해줘. 평균과 중앙값이 많이 다르면 그 이유도 설명해줘.
③ 대시보드 만들기첨부한 CSV로 현황 대시보드를 만들어줘. [제약] - HTML과 자바스크립트로만 구현 - CSV 인코딩을 자동 감지해서 한글이 깨지지 않게 - 컬럼 이름은 파일에 있는 그대로 사용 - 데이터가 0건이면 "완료"라고 하지 말고 빨간 배너로 실제 컬럼 이름 목록을 보여줄 것
④ 만든 것 고치기 — 대화로 이어서파일을 여러 개 올릴 수 있게 해줘 ○○ 기준으로 정렬할 수 있게 해줘 숫자에 천 단위 쉼표를 넣어줘 표를 엑셀로 내려받는 버튼을 추가해줘
⑤ 에러가 났을 때(에러 메시지를 그대로 복사해서 붙여넣고) 이 오류를 고쳐줘.
⑤번이 의외로 제일 많이 쓰입니다

에러 메시지를 이해하려 하지 마시고 그대로 복사해서 물어보십시오. 대부분 한 번에 고쳐 줍니다. 오늘 실습 중에도 이 방법을 여러 번 쓰시게 됩니다.

8막혔을 때

실습 중 자주 나오는 것들

증상해결
엑셀에서 한글이 깨진다 엑셀을 먼저 열고 데이터 → 텍스트/CSV 가져오기에서 원본을 UTF-8로 지정
Gemini에서 Canvas 버튼이 안 보인다 입력창의 + 또는 도구 메뉴 확인. 그래도 없으면 프롬프트 끝에 "Canvas로 만들어줘"를 붙이십시오
구글 시트에 Gemini 메뉴가 없다 Workspace Labs 가입이 반영되는 데 시간이 걸립니다. 새로고침하거나 재로그인. 회사 계정은 막혀 있을 수 있어 개인 gmail을 권합니다
배포했는데 화면이 안 나오고 파일 목록만 나온다 파일 이름을 index.html로. 전부 소문자여야 합니다
배포는 됐는데 숫자가 전부 0 컬럼 이름이 안 맞는 것입니다. F12 → Console 확인. 시트의 실제 컬럼 이름을 프롬프트에 그대로 적어 다시 요청하십시오
더블클릭하면 데이터가 안 나온다 실시간 대시보드는 배포한 https:// 주소로만 동작합니다 (5장 참고)
같은 프롬프트인데 옆 사람과 결과가 다르다 정상입니다. AI는 같은 입력에 같은 출력을 보장하지 않습니다. 그래서 검산이 필요합니다
어제 되던 게 오늘 안 된다 서비스 화면이 자주 바뀝니다. 강사 화면을 따라오시는 편이 확실합니다

9회사로 돌아가서

딱 하나만 실제로 써 보십시오

오늘 만든 것 중 하나만 살려두십시오

대시보드 하나든, 뉴스 자동 수집이든 상관없습니다. 안 쓰면 3일이 그냥 지나갑니다. 하나만 살려두시면 그게 계속 굴러갑니다.

시작하기 전 체크리스트

  • 이 데이터를 웹에 올려도 되는 데이터인가? (사내 데이터면 정적 방식으로)
  • 한 줄이 무엇인지 확정했는가? 행 수를 분해해 봤는가?
  • 빈칸이 몇 %인가? 20%가 넘으면 채우지 말고 원인부터
  • 더하면 안 되는 값(농도·비율)에 합계를 쓰고 있지 않은가?
  • AI가 낸 숫자를 아는 값 하나로 검산했는가?
  • 총 건수가 원본과 같은가?
가져가실 세 문장

1. 데이터를 만나면 "한 줄이 무엇인가"부터 확정합니다. 이게 안 되면 뒤에 뭘 해도 모래 위입니다.

2. 계산은 AI가, 기준은 사람이 정합니다. 무엇으로 묶을지, 평균이냐 최대냐 — 전부 사람이 정했습니다.

3. 만든 것은 반드시 검산합니다. AI가 만들어도 보고서에 이름 올라가는 건 여러분입니다.

도구 이름은 외우지 않으셔도 됩니다. 내년이면 화면도 이름도 바뀝니다. 위 세 문장은 안 바뀝니다.
